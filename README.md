# 映界 CineAtlas

个人使用的响应式影视聚合搜索与播放器。React / TypeScript / Vinext / Cloudflare Workers。

## 使用

进入「来源管理」添加来源：
- 普通网址：测试连通性，作为原站入口，不参与搜索。
- 苹果 CMS v10：提供兼容 `ac=detail`、`wd`、`ids` 参数且返回 `list` 的 JSON 接口。
- 声明式规则：HTML CSS 选择器（属性使用 `a@href`）或 JSON 点分隔字段映射。请求模板支持 `{query}` 和 `{id}`。

规则字段：`format`、`searchUrl`、`items`、`title`、`url`；可选 `detailUrl`、`id`、`poster`、`year`、`type`、`playback`、`episodes`、`episodeTitle`、`episodeUrl`。HTML 剧集列表的 `episodeUrl` 使用属性名，JSON 使用字段路径。规则不得包含脚本。测试显示匹配条数及前三个片名。

来源配置通过 JSON 导入导出。个人数据、收藏和进度保存在当前浏览器；「偏好与数据」提供导出和清理。不同浏览器或域名之间不会自动迁移。

## 开发

Node >=24.5。运行 `npm ci`、`npm run dev`。`npx tsc --noEmit` 检查类型，`node tests/adapters.mjs` 运行可控样例测试；`NODE_USE_ENV_PROXY=1 node tests/adapters.mjs --live` 另检查真实公开网址。`npm run build` 构建。

可在 Sites 服务端环境设置 `BRAVE_SEARCH_API_KEY`。未配置时仅聚合已启用来源，提供外部搜索入口。不会自动开通付费服务。

## 播放及边界

支持 MP4、WebM、HLS，HLS 优先原生播放，否则使用 hls.js。提供倍速、原生全屏、断点续播；地址不能直接识别为媒体时打开来源页面。播放器不绕过 DRM、登录或付费权限。服务端不代理、转码、下载或存储视频。网站规则不执行浏览器脚本，动态页面可能不可解析。

来源请求验证公开 HTTP/HTTPS 地址、DNS 结果和每一跳重定向，限制端口、响应大小与等待时间。DNS 验证与实际请求分离，不能代替运行平台的网络隔离；不应直接移除私有访问限制并作为公共任意 URL 代理运行。

## 本次验证

通过类型检查、生产构建、可控适配器测试（MacCMS、HTML/JSON、选集、去重、内网地址/重定向阻断、429）与 archive.org 真实连通性检查。本地 HTTP 首页 200，未配置搜索密钥返回正常降级状态。浏览器自动化连接超时，移动布局和真实 MP4/HLS 播放尚未完成浏览器验收。

UI 探索主题使用 Unsplash 远程图片，字体使用 Google Fonts；主题是检索入口，不是搜索结果。没有默认绑定未知第三方影视接口。


## 搜索升级（2026-11-08）

默认启用 Bangumi 动画/影视、TVmaze 全球剧集、Wikipedia 全球影视资料检索，无需密钥。个人非商业部署默认另启用 Bing RSS 网页检索；配置 Brave 密钥后使用 Brave。来源管理可单独停用内置资料源，已有自定义来源和个人数据保留。

支持中英文、数字与中文混写的片名规范化及缩短关键词回退，例如 `86不存在的战区` → `86 不存在的战区` → `86`。资料结果标注为「作品资料」，不会冒充可播放资源；检索到的已知平台视频页面优先显示，跳转原站播放。平台搜索入口另行明确标注。

新增 `GET /api/catalog?provider=bangumi|tvmaze|wikipedia&q=...`，按来源独立请求、逐批呈现。公共资料短暂缓存五分钟，单个来源失效不阻塞其他来源。未配置任何自定义来源或搜索密钥，也能检索。来源资料遵循原站许可，条目链接原站。Bing RSS 仅供个人非商业使用。

`node tests/search.mjs` 测试查询规范化、相关性排序、回退、资料标签、缓存、429、观看页面分类及伪造域名。加 `--live` 验证真实免费接口，网络异常会令实时测试失败，不会用样例代替。

## 局域网与资源优先模式

`npm run dev` 默认监听 `0.0.0.0:5173`；`npm start` 同样绑定所有网络接口。当前局域网地址为 `http://192.168.2.10:5173`（地址变化时以终端 Network 输出为准）。同一局域网的设备可访问，收藏和来源仍按浏览器分别保存。云端部署继续保持私有。用户的局域网默认偏好记在 Codex 项目根目录的 AGENTS.md 中，适用于其下后续项目。

默认「仅影视资源」模式排除作品资料、百科、论坛、小说漫画、首页、分类页与搜索页。已知影视来源的详情/播放页面优先展示；未知网站需同时匹配影视作品路径与观看标题特征。可切换「含作品资料」「全部网页」，或在偏好中增加排除域名。

内置 AGE（age.tv 当前重定向至 www.agedm.io）与 Movieffm（mvffm.net）专用适配器，首次升级自动加入现有来源列表，之后可停用、删除、编辑与导出。AGE 支持搜索、详情与原站选集；Movieffm 支持搜索及原站作品播放入口，动态播放器不通过执行第三方脚本解析。简繁体、符号、数字与中文混合查询以及部分译名差异有相关性匹配，防止「86」回退带入无关短剧。

新增 `node tests/sites.mjs` 测试资源过滤与站点解析；加 `--live` 检查两个真实站点及 AGE 选集。平台可能改变域名、结构或访问策略，失效会独立提示，不会将占位数据当作成功。


本地开发通过 Node 网关在 5173 提供页面和 API，Vinext 只在内部 5174 运行，避免 Worker 本地模拟器与本机代理的外网兼容问题；API 使用与云端相同的源代码和网址安全校验。启动命令自动使用系统代理环境配置，不改变系统代理。需要 Node >=24.5。关键字排名依次考虑完整匹配、前缀、包含、别名、中文近似以及受限的拼写编辑距离；短数字（如 86）保留包含结果并将标题前缀排在前面。


## 紧凑搜索与检索增强

完成搜索后首页宣传区自动精简为搜索栏，隐藏右侧装饰图；结果先展示影视作品，再展示网页观看入口和默认折叠的播出平台。展开平台使用原生 details/summary，可用键盘操作，新一次搜索会重置为收起。

来源搜索依次尝试原始关键词、规范化片名、短关键词与中文核心词（最多四组，有结果即停止），扩展结果必须通过相关性过滤。正结果缓存两分钟、空结果十秒，相同来源配置和查询的并发请求合并；修改来源配置后缓存隔离。作品目录识别出正式名称/别名后，会为首轮无结果的来源补充一次检索。快速切换查询会取消旧的浏览器请求，并用查询代次校验避免旧结果覆盖新结果。资料结果始终排在实际影视来源之后。

新增 `node tests/source-search.mjs` 验证关键词回退、无关结果过滤、去重、缓存、来源配置隔离、并发合并及别名生成。

Scrapling 评估：https://github.com/D4Vinci/Scrapling 。其提供 Python 解析、请求、浏览器渲染与爬虫组件。当前应用保持 TypeScript/Vinext，未安装或接入 Scrapling；如后续需要，可通过独立的本地 Python 服务对接已有适配器，网络请求仍需执行公开地址验证与重定向检查。现有静态页面采集已由原生请求和 Cheerio 完成，不把库本身当作额外搜索引擎。


## 欢乐好声音搜索修复与 Movieffm 站内播放

搜索归一化使用 opencc-js 的完整繁体转简体转换，替代之前不完整的字符表。斜线分隔的片名按别名匹配，因此「欢乐好声音」能识别「歡樂好聲音/星夢動物園」，原作的别名精确匹配排在续作和短片之前，同时排除「中國好聲音」等不同作品。

Movieffm 详情解析仅提取页面中公开 JSON 格式的 videourls 数组，按页面所用的 Base64/URL 编码还原视频地址，不执行第三方 JavaScript。支持公开 HLS/MP4 线路，排除 iframe 和非 HTTP/HTTPS 协议。详情页探测前三条线路的响应状态，优先排列可达媒体类型，保留其他线路供手动尝试。探测可达不等于完成浏览器解码验收。

详情提供「站内播放」入口。播放器支持线路切换、下一线路、错误反馈、倍速和进度恢复。视频直接由浏览器从来源加载，不通过本应用代理或存储；跨域、地区、编码、失效地址及原站访问规则仍可能影响播放。

验证：`node tests/sing-playback.mjs`；加 `--live` 检查真实搜索与播放线路提取。实际站点返回原作、续作和短片共三条相关结果，原作详情公开 18 条 HLS 线路；抽测多条清单 HTTP 200 且允许跨域，第一条已失效。浏览器自动化工具连接超时，未完成实际音视频播放验收。


## AGE 云端受限、完整性提示与本机辅助

实测同一「86」查询：AGE 原站与本机服务返回两个条目，云端访问 AGE 返回 HTTP 403。应用将来源访问失败明确展示为结果不完整，提供「重试来源」「本机辅助检索」及携带当前关键词的原站入口。

对于 403/408/部分 5xx，同一地址最多附加重试两次，间隔 400ms、900ms；网络异常最多附加一次。429 不自动连发，避免进一步触发限流。不会通过更换身份、代理或绕过验证码来重试。403 若持续出现，重复请求不保证恢复。

本机辅助在偏好中默认关闭，也可在来源受限提示中主动点击启用。默认地址 http://127.0.0.1:5173，同一局域网其他设备可改为运行服务的电脑 IP。需保持 `npm run dev` 运行，并由用户在浏览器提示时允许访问本地网络。只有当前映界云端 Origin 被本机 API 的跨域白名单接受，其他站点被拒绝；不启用通配跨域或跨域凭据。辅助只传递本次来源配置与查询，收藏/进度仍留在当前页面。来源详情也沿用成功的本机通道。

AGE 搜索自动读取后续分页，兼容苹果 CMS 接口同步读取 pagecount 对应的后续页；每个关键词最多三页。不同关键词和最多六个目录别名会合并去重，不再因为第一组已有结果而跳过其他检索。单次检索有时间/页数上限，达到上限或部分分页失败会显示完整性提示和原站更多入口。实测「高达」由原先第一页 24 个条目补至两页 30 个条目；「86」和已识别的英文别名 Eighty Six 均能检索两个 AGE 条目。

`node tests/coverage.mjs` 覆盖分页、部分覆盖状态、别名检索、关键词合并、有限重试、429、跨域白名单及本机地址限制。真实 API 已测试云端 Origin 到本机的预检/搜索响应；浏览器端本地网络许可仍须由用户确认，未以自动化代为授予。


## AGE 在应用内播放（不自动跳转）

AGE 选集页目前提供的是第三方播放器 iframe 地址，而非直接公开的 HLS 地址。新增 `action: playback` 仅对 AGE 的合法选集页面解析，优先使用页面明确提供的视频 src，否则解析其原有 iframe；不解密不透明播放参数，不执行源站脚本来获取直链。

点击 AGE 选集后，在本应用播放器弹窗内嵌入来源播放器，可切换同一播放源的下一集和全屏。框架沙箱不允许弹窗或顶层导航，因此应用不会因选集按钮自动跳到新标签页。倍速与进度由内嵌来源自身提供，应用无法跨域读取它们。已有 Movieffm HLS/MP4 继续使用原生播放器。

来源视频或 iframe URL 均验证公开地址与协议。仅 iframe 地址额外允许 AGE 实际使用的 8443 端口；普通来源抓取的端口限制不变。线上 AGE 抓取若受限，可沿用本机辅助通道解析选集。页面必须允许被嵌入，应用不会代理修改 X-Frame-Options/CSP 或绕过来源限制。

验证：`node tests/age-embed.mjs`；`--live` 实测第 6 集解析出内嵌播放器、播放器页面 HTTP 200，未观察到禁止嵌入响应头。浏览器自动化仍连接超时，实际声画播放需用户验收，页面加载成功不能代表视频已播放。
